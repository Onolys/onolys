# Code Run — SP5 / Task 5

Branch: `feat/miti-eval`. Scope: background run creation/execution/cancellation only.

## Changes and criteria

- `POST /v1/runs` validates the actual engine/preset catalog, excludes `test-*`, checks strict 1|3 repeats, validates dataset session membership or saved-upload readiness/gold eligibility, roles and coding limits before writes. Dataset goals/spans come from each session manifest; uploads preserve saved settings or request overrides.
- Copies resolved transcript/gold into private immutable run input paths, hashes canonical contents, preserves provenance, effective goal/language/span and the actual observed speaker map (`subject` = clinician, `other` = client).
- Saves creator from `request.state.admin_claims`, engine versions, repository git SHA and resolved preset/model map. No provider keys enter these records. Build provenance uses `GIT_SHA`/`COMMIT_SHA`, with source-checkout git fallback.
- Expands Human once per session and AI units over session × engine × preset × repeat. One atomic parent/unit repository batch; validates Firestore's 499-unit platform bound before publication. Enqueues JSON/OIDC `unit` jobs through the existing queue and 900-second dispatch deadline.
- Unit claims and terminal counters use pure `transact_unit` callbacks. Concurrent or terminal duplicate deliveries cannot rerun the engine or double-count completion. Final status is done for all successes, partial for success plus another terminal outcome, failed when none succeeded.
- AI units build a lazy preset-resolved core client, fresh metrics collector and `RunContext` with an 840-second deadline; the shared `run_validated` wrapper is the sole engine entry. Preset, config variant, span, goal, language and observed speaker map reach the engine. Execution has a matching bounded async timeout.
- Adapts lean and one-shot results through eval adapters; Human reads gold directly without an LLM. Human uses gold's span and records `human_span_differs` where needed.
- Stores scores, run information and inline/spilled output. Failed output validation retains the wrapper's typed billable usage; other failures retain the metrics collector's usage. Provider costs win; per-model metadata supplies estimates; unknown/broken prices remain explicitly unpriced. Errors use fixed public codes without exception text.
- Cancel marks the parent flag, immediately terminalizes queued units and leaves in-flight calls to finish. Pending deliveries no-op; cancellation alone cannot leave pending units running.
- Enqueue failure terminalizes only still-queued units with `enqueue_failed`; accepted/claimed work keeps ownership. The API still returns the saved run ID. Successful peers produce a partial run, and the saved input supports a later rerun.
- Exposes an internal-only `create_run(..., input_ref=saved_run['input_ref'])` seam for Task 6. It verifies snapshot integrity and reuses immutable input independently of mutable dataset/upload source objects. No history/compare/rerun endpoint was implemented.

## Deviations / operational limits

- An enqueue exception is recorded as a terminal failed unit, rather than leaving an undelivered queued unit. Retry is a new run using the preserved input; this was coordinated with the orchestrator.
- Hard process loss between parent creation and enqueue, or after claiming and before terminal persistence, has no automatic recovery lease/outbox/reaper. A still-running duplicate is acknowledged to prevent concurrent duplicate provider work. Operator cancellation terminalizes pending units; an interrupted in-flight unit requires operator recovery/rerun. The normal 840-second timeout records engine timeouts before the queue's 900-second deadline. Distributed crash recovery is not introduced by this task.
- The internal helper copies immutable bytes/settings into the new run, while engine/preset models resolve from the current configured catalog, as expected for a fresh evaluation.
