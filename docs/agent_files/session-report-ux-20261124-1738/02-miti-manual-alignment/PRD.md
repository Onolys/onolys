## TL;DR
Code counts, 4 globals and summary formulas already match the manual [eval; spot-rechecked p.32-33]. Three real deviations remain: any client turn, even "mm-hm", breaks a volley [verified: `pack.yaml:268-271`, `prepare.py:113-135`]; a volley can score both Persuade and Persuade with Permission [verified: `score.py:44`, `pack.yaml:256`]; globals are overwritten with 3 when fewer than 2 quotes locate [verified: `globals_pass.py:180-196`]. Fix those, add bounded client context and an info-only coverage metric, and show the effect with an offline audit report. Claim: manual alignment and non-regression of the deterministic parts, not accuracy.

## Problem
- Over-parsing: facilitative speech ends volleys, so once-per-volley codes (Q, GI, SR/CR, AF...) are counted more often than the manual allows [manual p.13, p.15-16].
- Persuade and Persuade with Permission are one slot; today both can count in one volley, inflating Total MINA [manual p.13; p.33].
- The reset pulls good and poor sessions to 3, contrary to "start at 3 and move up or down" [manual p.4], and to "high SST with no sustain talk" [manual p.7, p.38 FAQ 6] and "do not penalize when no change talk" [manual p.5].
- Permission "may last several minutes" and can come before, during or after persuasion [manual p.18-19]; it is asked by the clinician, so it may sit in the previous batch; the coder sees one prior client turn [verified: `code_pass.py:~158`, `prepare.py:29`].
- Uncovered clinician speech is not measured; silent drops are invisible.
- `_words` is `len(text.split())` [verified: `prepare.py:50`]; spaceless scripts (Thai, Chinese, Japanese, accepted per `languages.py`) count every turn as 1 word.

## Goals / Non-Goals
**Goals:** manual-faithful volley parsing, persuasion slot and globals; bounded context; coverage visibility (info only); a deterministic offline audit (baseline at HEAD vs each step); two new fixtures plus a batch-edge fixture; goldens kept green at every step by an offline regeneration script.
**Non-goals:** accuracy claims without human-coded data; any live LLM call or API key; latency/token/cost measurement; report schema change or null globals (the manual has no "no score": every review has four globals, p.3); quote-validation rework (`locate` already validates [verified: `code_pass.py:177`, `globals_pass.py:140`]); compact anchors (transcript is not repeated per batch); tips context (`tips.py:100`); any API/web change; new protocols (mission); a coverage retry.

## Requirements
**R1 Volley breaks.** A client turn does not break a volley when it is facilitative, unless it answers a direct clinician question. Implement in `build_volleys`: a client turn is facilitative when its size is below the threshold; it is skipped (not codable). Pack: `min_other_words: 3`, `min_other_chars: 6` [eng]. The clinician turns on both sides then form one volley.
- Size measure `_size(text)`: for spaced scripts, `len(text.split())` vs `min_other_words`; for spaceless scripts (Thai, Chinese, Japanese: text where at least half of the letters are in those Unicode blocks), count non-space characters vs `min_other_chars`. Test per script (see AC1).
- Question exception: the turn still breaks when the previous clinician turn "asks a question", defined precisely: strip trailing whitespace and closing quotes/brackets; the turn's last sentence ends with a question terminator `?`, `？` (U+FF1F) or `؟` (U+061F), or a question terminator is followed only by a fragment of at most 3 words/6 characters ("What happened? Go on."). A question earlier in a longer clinician turn does not count.
- Trade-off [eng]: threshold 3 treats "yeah, right, good" (3 words, the manual's client facilitative example [p.13]) as facilitative, and keeps short change talk of 3+ words ("I can do that") as a break. Short 1-2 word change talk after a statement ("Maybe." "I will.") is skipped and may merge volleys, which can undercount reflections slightly; accepted, since the manual prefers fewer parses [p.14, p.16]. A higher threshold (5) swallowed "I can do that"; rejected.
**R2 One persuasion slot.** Pack rule `exclusive_group`, unit volley, `codes: [persuade_permission, persuade]`, `precedence: [persuade_permission, persuade]`; the loser is down-counted `superseded_by_persuade_permission` [existing mechanism, `score.py:57`]. Prompt/pack text states the same-utterance rule [manual p.20]. Note: `globals_system.md`-style text is not involved; only `code_system` prompt and pack text change.
**R3 Globals.** Delete the reset branch in `_rate`; the model's score stands, cap-on-poor-practice unchanged. Keep `insufficient_evidence` as an `info` diagnostic with no "reset" wording. Stop emitting `source: "default"`. Prompt: `globals_system.md` already says start at 3 and move with evidence [p.4] and not to penalize SST/CCT without change talk [p.5, p.7, p.38] [verified in the file]; the only new line is: low scores need evidence of the clinician behavior, not of its absence. Empty `evidence` is allowed: `report.schema.json` `OnolysGlobal.evidence` has no `minItems`, `source` already includes `default`, and web reads `?? []` (`codedRows.ts:85`) [verified; no schema/web change].
**R4 Bounded context + guard.** Per volley, `context_before` is text only (no turn ids), user message only [verified: `_render_batch`], replaces `previous_other_turn`:
- Client part: the last up to 4 client turns before the volley, at most 150 words in total (drop oldest whole turns; if the newest alone exceeds 150, keep its last 150 words; spaceless scripts count characters, 300).
- Clinician part: the previous clinician volley text (the volley before this one, even when it lies in the previous batch), bounded to its last 100 words, labelled context only. Reason: permission is asked by the clinician [p.18 item 2] and may sit in the previous batch.
- Guard (diagnostic relabel): `_locate_volley` searches only the batch's own turns [verified: `code_pass.py:~177`], so a quote taken from context already fails as `quote_not_found`. R4 adds a cheap check: when a quote is not found in the batch's turns but is found in that volley's context text, the warning is `context_quote` instead of `quote_not_found`. It does NOT count toward `MAX_DROP_RATE` (`code_pass.py:33`): the utterance is dropped either way, but a context quote is a known, bounded model confusion, not evidence of a bad batch, and a retry would resend the same context. Each instance's turn id must belong to its batch; batches stay disjoint.
**R5 Coverage metric (info only).** After location, compute clinician words not covered by any located utterance, per volley and per run. Emit info warning `coverage_gap` when a volley with at least 40 clinician words returns no utterance [eng threshold]. A coverage gap never raises `CodePassFailed` and never triggers a retry: it cannot be calibrated offline and a retry costs live calls. [DEFERRED: coverage retry, if human-coded data or live runs exist later.]
**R6 Deterministic offline audit report.** New script (in `engines/miti`, e.g. `audit_report.py`, no network, no client) that runs `prepare` (volleys) and `score.apply_rules` over all fixtures at HEAD (baseline) and after each step, and writes a table: volley count, batch count (25 volleys per call), rendered-request words (proxy for tokens; no token gate), persuasion double counts on recorded/hand-authored instances (target 0 after step 2), coverage residual on hand-made instances. Committed output: `02-miti-manual-alignment/measurements/{baseline,step1..step5}.json` and `summary.md`. No latency, p95, token or cost numbers, no `--n-runs`, no `check.py` change. `check.py` live smoke stays as is, untouched and not part of this plan.
**R7 Fixtures.**
- (a) `batch_edge`: small committed fixture (~1,500 words, 26+ volleys) so the 25-volley batch edge falls inside a permission-then-persuade pattern, with facilitative "yeah"s and a question-answer "yeah". The 6,000-word size case is an in-test generator (`tests/`), not a committed fixture.
- (b) `sparse_evidence`: short, little change talk, no sustain talk (expect SST 4-5, p.38).
- `expected.yaml` for new fixtures asserts a `volleys:` structure (count and which turn ids group together), checked in `test_prepare`; code counts are checked by `score.apply_rules` on hand-authored instances (no model output). Each count carries the rule/page behind it. Audit existing `expected.yaml` against R1 and change an expected count only where the manual requires it.
**R8 Goldens green at every step.** `test_golden.py:88-110` freezes exact request hashes and `FixtureClient` raises `FixtureMiss` on any change [verified: `fixture_client.py:52`]; R1-R4 each change requests. The existing goldens are synthetic stubs, not live recordings (the test docstring says so), so they can be regenerated offline. Provide `engines/miti/tools/regen_goldens.py`: rebuild the requests for each fixture, compute `FixtureClient.key_for`, write golden files reusing the previous responses (hand-edit volley ids/quotes where structure changed), and update the `expected` hash set in `test_golden.py`. Behaviour tests for R4/R5 use a `StubClient` (callable that answers from the rendered batch JSON: echoes a volley id and quote picked from the batch) instead of goldens.

## Architecture
Order and commits (each commit is green and is an audit point): 0 baseline audit on current HEAD (no code change), 1 volley break (R1, regen goldens), 2 persuasion slot (R2, regen), 3 globals (R3, prompt line, regen), 4 context + guard (R4, regen), 5 coverage metric (R5, regen if needed). Each commit contains its code, tests, regenerated goldens and `measurements/stepN.json`. No "re-record once" step: any step that changes a request hash regenerates goldens in the same commit. The cache prefix (`cache_prefixes`, `code_pass.py:~131`) must stay byte-identical across batches of a run; the R3/R4 prompt edits change it once versus baseline, which is expected. Volley ids change when R1 merges volleys; goldens, `code_fewshot.json` and `expected.yaml` follow.

Tests that must be updated: `tests/test_prepare.py:136-163` pins `prev_other` and "mm-hm breaks volley by default" (rewrite to the new rule); `data/prompts/code_fewshot.json` has `previous_other_turn` (~lines 7, 25), replace with `context_before` and update few-shot volley text.

## Acceptance Criteria
1. **Volley tests** (tiny hand transcripts in `test_prepare.py`, replacing the pinned `prev_other` / "mm-hm breaks" tests at 136-163): clinician / "yeah" / clinician = 1 volley; clinician ending "?" / "yeah" / clinician = 2; clinician ending "？" and "؟" likewise = 2; question terminator followed by a 2-word fragment = 2; question earlier in a long clinician turn, last sentence a statement = 1; client turn of 3+ words ("I can do that") breaks; facilitative turn is not codable but is available as context; spaceless-script test (Thai/Chinese client turns of various lengths: a long Chinese client turn breaks, a 2-character one does not, session is not one volley); fixture `volleys:` structure in `expected.yaml` matches `build_volleys`.
