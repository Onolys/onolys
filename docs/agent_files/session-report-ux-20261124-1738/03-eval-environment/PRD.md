## TL;DR
Eval today is hand-written Terraform bound to the staging database [verified: `infra/eval-services.tf` `FIRESTORE_DATABASE = "staging"`, condition `databases/staging`]. This SP (1) makes eval a third module instance with its own data, queue, bucket, secrets and login allowlist, (2) removes the legacy staging eval service now (eval is unusable until SP05; accepted by owner), (3) removes every remaining admin resource, variable, output, test, doc, CI var and name (admin app source already retired in `23c747f`), (4) makes eval sign in through the prod app's own login (one auth codebase, same Firebase user pool; the separate `eval/auth` package and eval web auth copy are deleted), (5) drops the Terraform budget so console-set limits are not overwritten. **Execution policy (owner 2026-11-25):** agents build everything and run offline tests only; no `terraform apply`, no deploy, no live LLM/STT runs; the owner runs plan/apply and the first eval. New module variables default to "off", so staging/prod plans show only the admin deletions (and `moved`/`removed` bookkeeping).

## Goals / Non-Goals
**Goals:** `module "eval"` with isolated DB/bucket/queue/SAs/secrets; eval signs in with the prod app's login (one copy of auth code, same user pool); staging/prod plan shows only admin deletions; eval-only surface is allowlist-gated; datasets bucket readable, never writable, by the eval runtime; eval runs are fully server-driven (owner may close the browser; the run completes); zero admin infra/names left and no `eval/auth` package; no Terraform budget; offline-checkable (`fmt`, `validate`, static tests).
**Non-goals:** eval backend behaviour (SP05), `is_eval` / worker honouring (SP04), eval web UI (SP07), applying anything, seeding provider-key secrets, moving/renaming the datasets bucket, setting spend limits (owner, consoles), any apply/deploy/live run (owner), a read-only service account for agents (dropped by owner).

## Architecture
```
GitHub CI --digest(staging image)--> onolys-worker-eval  <--OIDC-- Cloud Tasks steps-eval (cap >= 2 x providers + ticks)
          --eval/backend image-----> onolys-eval-backend-eval (allowlist eval-allowed-emails-eval, SA api-eval)
Firebase Hosting onolys-eval-staging (eval.onolys.com; prod login, prod web app config) --> eval-backend-eval
eval-backend-eval/worker-eval --> Firestore db `eval` | gs://onolys-audio-eval (runs, gold/, eval-uploads/) | secrets *-eval
eval-backend-eval --read-only--> gs://onolys-eval-data-staging (datasets)
Browser is read-only/poll: runs continue server-side if it closes.
```
Isolation: DB, bucket, queue, SAs, secrets are per module instance; IAM conditions pin `datastore.user` to db `eval` [verified: `main.tf` `datastore_user`]. No `api`/`voice` service exists in eval, so no public sign-up path can spend eval budget. Admin is gone entirely; `admin.onolys.com` serves nothing.
