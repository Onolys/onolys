## TL;DR
Eval today is hand-written Terraform bound to the staging database [verified: `infra/eval-services.tf` `FIRESTORE_DATABASE = "staging"`, condition `databases/staging`]. This SP (1) makes eval a third module instance with its own data, queue, bucket, secrets, Firebase web app and login allowlist, (2) removes the legacy staging eval service now (eval is unusable until SP05; accepted by owner), (3) removes every remaining admin resource, variable, output, test, doc, CI var and name (admin app source already retired in `23c747f`; eval login currently leans on admin pieces), (4) drops the Terraform budget so console-set limits are not overwritten. New module variables default to "off", so staging/prod plans show only the admin deletions (and `moved`/`removed` bookkeeping).

## Goals / Non-Goals
**Goals:** `module "eval"` with isolated DB/bucket/queue/SAs/secrets/web app; staging/prod plan shows only admin deletions; eval-only surface is allowlist-gated; datasets bucket readable, never writable, by the eval runtime; eval runs are fully server-driven (owner may close the browser; the run completes); zero admin infra/names left; no Terraform budget; offline-checkable (`fmt`, `validate`, static tests); owner-run security runbook prepared.
**Non-goals:** eval backend behaviour (SP05), `is_eval` / worker honouring (SP04), eval web UI (SP07), applying anything, seeding secrets, running the read-only SA script, moving/renaming the datasets bucket, setting spend limits (owner, consoles).

## Architecture
```
GitHub CI --digest(staging image)--> onolys-worker-eval  <--OIDC-- Cloud Tasks steps-eval (cap >= 2 x providers + ticks)
          --eval/backend image-----> onolys-eval-backend-eval (allowlist eval-allowed-emails-eval, SA api-eval)
Firebase Hosting onolys-eval-staging (eval.onolys.com, own web app `onolys-eval`) --> eval-backend-eval
eval-backend-eval/worker-eval --> Firestore db `eval` | gs://onolys-audio-eval (runs, gold/, eval-uploads/) | secrets *-eval
eval-backend-eval --read-only--> gs://onolys-eval-data-staging (datasets)
Browser is read-only/poll: runs continue server-side if it closes.
```
Isolation: DB, bucket, queue, SAs, secrets are per module instance; IAM conditions pin `datastore.user` to db `eval` [verified: `main.tf` `datastore_user`]. No `api`/`voice` service exists in eval, so no public sign-up path can spend eval budget. Admin is gone entirely; `admin.onolys.com` serves nothing.
