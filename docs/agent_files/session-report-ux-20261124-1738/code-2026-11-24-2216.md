# Product error recovery and API documentation

Branch: `session-report-ux`. Light-mode follow-up; implementation and tests are in this commit.

## Changes

- Generic accessible recovery uses fixed copy, focused heading, reload and a native link back to the start. Displays actual HTTP status and request references matching the backend's safe identifier format; never renders exception messages or response bodies.
- Recovery covers React failures above the router/providers, shell crashes, page crashes, and essential initial reads for sessions, reports, interview/scenario pages and session status fallback. Existing local validation/auth/not-found/limit errors and failed-run cards retain their behavior. Background errors retain usable data; session status also retains its last live document if fallback polling fails.
- Initial HTML contains native recovery links even without JavaScript/CSS. A separate same-origin classic script handles early script/import errors and rejected startup promises while the static fallback exists. No inline script or styles; the production build retains the fallback and recovery script.
- `/v1/docs`, its vendored script and `/v1/openapi.json` mount only with `ENV=local|test`; staging/production respond with the existing JSON 404 contract. In-process OpenAPI generation remains available. API authentication and key endpoints are unchanged.
- Internal reference and generated OpenAPI introduction reflect local documentation access and API-based key creation; generated web types are unchanged.

## Limits

These are application recovery surfaces. They cannot replace a hosting/CDN response when the initial HTML itself is unavailable or rejected. Native links still work if the recovery script cannot load. Client-side recovery does not rewrite HTTP statuses or API JSON responses. No live providers, deployments or real-browser session were used; browser behavior is covered by DOM tests and the production-build CSP checks.

Whole-branch review and shipping remain with the parent orchestrator. No owner-only actions block this implementation.
