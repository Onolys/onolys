Repo/branch: Onolys/onolys / `refactor/revamp` · Depends on: 04-engine-package (hard: `onolys_engine` public surface, STT/voice/rating already moved into `api/`); 03-eval-split (hard: eval gone, eval-mode code is ours to delete; eval keeps its own `config/` copy); 01-legacy-purge; 02 (Auth emulator block in `api/firebase.json`) · Owns: `api/**` (src, tests, `scripts/dev.sh`, `README.md`, `firebase`-using test fixtures), the `api-*` jobs in `.github/workflows/ci.yml`, `api/openapi.json` + `docs/contracts/public` (regenerate only; must not change) · Does not own: engine (04/05), web (07, 08), `infra/`, `config/` relocation and `firebase.json` consolidation (09), `docs/`.

## TL;DR
`api/src/onolys_api` becomes one folder per feature (`sessions/ audio/ transcription/ pipeline/ tasks/ data/ usage/ auth/ email/ voice/ rating/ routes/`); `jobs/ adapters/ repo/ storage/` disappear. Data access is five base functions (`get_doc set_doc update_doc query in_transaction`, owner check inside) plus one-line wrappers, written once. The leaf features `data/ auth/ tasks/ transcription/` import nothing from `routes/ sessions/ pipeline/`, take explicit settings/clients, expose separately named ownerless data functions (eval only) and ship an in-process queue stub, so the eval repo (10) imports them instead of copying. No fakes: tests and local dev run the real code against the Firestore and Auth emulators plus small stub clients (local-folder blobs, in-process queue, recording email, fixture STT/LLM/voice). CI already runs the Firestore emulator (Java 21 + firebase-tools, cached), so the cost is test time, not new tooling. The public HTTP contract does not change; CI's existing regeneration diff proves it.
