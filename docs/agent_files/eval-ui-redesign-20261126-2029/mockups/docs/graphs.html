Cross-cutting rules (from prior PRD): every chart has a one-sentence caption and a table twin behind "Show data"; shape + letter + colour, never colour alone; the UI computes no metric; n shown wherever a value is shown.

Charting library

Recommendation: keep hand-rolled inline SVG (no library), with one shared scale/axis helper.

  • eval/web/package.json has no chart dependency; prior PRD decision #1 chose hand-rolled SVG/CSS; the mockups in this package are built that way, so what you review is what ships.
  • The chart set is small (dots, bars, grids, two scatters). Full control of keyboard focus, ARIA and table twins; deterministic jsdom tests; no bundle growth; no supply-chain addition.
  • Recharts / ECharts: 100-300 kB+, themes fight Tailwind tokens, weaker a11y control. Not worth it for 6 chart types.
  • If chart count grows (brushing, zoom, tooltips on many points): add visx (modular, tree-shakable, React-native SVG) rather than Recharts/ECharts.

Fixes to current charts

  • Dot plot label overlap: reserve a fixed left gutter for row labels; plot area starts to the right; axis ticks only above the plot area; one vertical lane per series.
  • All charts inside cards with title, caption, legend; no horizontal scroll (scale via viewBox, stack to one column on narrow screens).
