Design rules (draft for docs/design-rules.md)

Apply to eval/web and any new UI built on @onolys/ui tokens.

1. No horizontal scroll, anywhere

Tables must fit the viewport. Handle overflow by wrapping, truncating with a tooltip, or stacking rows into cards below 760 px.

  • Do: fixed table layout with column widths, ellipsis + title tooltip for long model names, stacked cards on mobile.
  • Don't: wrap tables in overflow-x:auto; hide data off-screen; put ids inside buttons.

Check: page scrollWidth equals clientWidth at 390 and 1440 px.

2. All configs open in a popup

Any "Config" action opens a modal: key facts as tiles, combo list, raw JSON behind a disclosure with Copy. Errors and raw output also open in popups; ids go inside the popup, not on the trigger.

  • Do: button "Config" opens modal; "View JSON" opens modal titled with the unit id.
  • Don't: render config inline or as a navigation.

3. Format everything: no plain text for data

Statuses are colour-coded chips with icons (never colour alone). Group related info in cards. Counts and metrics are stat tiles. Failures are red and shaded; warnings amber; success green; zero values muted.

  • Do: [spinner Running] [check 4 of 8 done] [x 1 failed].
  • Don't: "running · 1/3 runs done · 1 running · 0 failed".

4. Table headers are headers, not buttons

Column headers are plain th elements. Sortable columns show up/down arrow indicators (aria-sort, keyboard operable). No button styling on headers.

  • Do: "COST" with stacked arrows, active arrow in primary colour.
  • Don't: render headers as pill buttons.

5. Notes and caveats are muted and small

Footnotes, definitions and caveats use muted foreground colour at about 12-13 px, below the content they explain. Failed or invalid items never count toward "best".

  • Do: small grey note under the table.
  • Don't: body-size plain paragraph that competes with data.

Tokens

Use @onolys/ui tokens (primary #0b5f5a, success #166534, warning #854d0e, destructive #8a3030, score-good/fair/low and their backgrounds, radius .5rem). Titles follow "Page - name".
