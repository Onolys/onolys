# Review 2026-11-26 round 1: ci/terraform-plan-apply

Verdict: NEEDS_CHANGES (all items below fixed in the fix round, see commits after f1811abb; re-review pending).

## Security (must-fix)
- S1 `roles/firebaseauth.viewer` grants `firebaseauth.users.get`: any same-repo PR could dump all Auth users. Fixed: dropped; custom role gets `firebaseauth.configs.get` only.
- S2 `roles/cloudtasks.viewer` grants `tasks.get/list/fullView` (task bodies hold uid, sid, email). Fixed: replaced by `cloudtasks.queues.get/list/getIamPolicy` and `locations.get/list` in the custom role.
- Audit via `gcloud iam roles describe`: also removed `iam.securityReviewer` (`logging.logEntries.list`, `privateLogEntries.list`, `storage.objects.list`, `cloudtasks.tasks.list`), `monitoring.viewer` and `serviceusage` viewer/consumer (`monitoring.timeSeries.list`), `artifactregistry.reader` (`files.download`). Kept (verified metadata-only): run.viewer, secretmanager.viewer (no `versions.access`), cloudscheduler.viewer, iam.serviceAccountViewer, iam.roleViewer, iam.workloadIdentityPoolViewer, firebasehosting.viewer. Role snapshots checked in; a test denies data-read permissions.
- S3 plan provider admitted any event on main. Fixed: `event_name in [pull_request, push, workflow_dispatch]` and `job_workflow_ref` starts with the terraform.yml path.
- S4 apply impersonation scope. Fixed: dedicated `github-apply` pool per project (deployer providers untouched), bound to `attribute.workflow_ref` = terraform.yml@refs/heads/main; prod provider also requires environment `terraform-prod`.
- S5 unpinned `pip install` after auth. Fixed: hash-pinned requirements, installed before auth with `--require-hashes`.

## Bugs (must-fix)
- B1 `tf_plan_summary.py` KeyError on `forget`; summary failure was swallowed. Fixed: forget supported, unknown actions counted, step fails on summary error.
- B2 missing permissions (log-based metric get/list, `logging.configWriter`, plus found by the mapping test: `datastore.indexAdmin` for `google_firestore_field`, Cloud Tasks queue, Artifact Registry repo, alert policy, channel, Identity Platform config, Service Usage reads). Fixed with a resource-to-permission table and tests; `plan_extra_permissions` variable added.
- B3 plan/apply drift on deploys: apply now re-reads live inputs and aborts with "re-run to re-plan" on hash mismatch. Limitation documented (`git_sha` read from worker only; variable is shared).

## Architecture (must-fix)
- A1 apply-prod asked for approval even with no prod changes. Fixed: `gate` job exposes `prod_changes`.
- A2 stale "manual apply" docs. Fixed: infra.md, isolated-environments.md point to infra-pipeline.md; ADR 0026; architecture.md line.
- A3 advice to make path-filtered plan jobs required checks removed.

## Should-fix (done)
Reuse of WIF_PROVIDER / STAGING_WIF_PROVIDER / EVAL_WIF_PROVIDER with derived names (new variables: three enable flags), shared composite action, per-env gating, 7-day lifecycle for `plans/`, dispatch only on main, `infra` split into `infra` + `infra-isolated` (5 min each, in the required gate), legacy-destroy prerequisite documented (read-only prod plan on 2026-11-26: only `module.terraform_ci` creates).

## Deviations
- Composite action instead of reusable workflow `_terraform-apply.yml`: a reusable workflow changes `job_workflow_ref` (breaking the workflow binding) and cannot take an optional Environment reliably.
- Dedicated apply pool instead of adding `workflow_ref` to the deployer providers: avoids touching deployer bindings and makes the prod environment requirement enforceable in the provider condition.
